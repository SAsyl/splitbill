# splitbill — делим счёт без калькулятора

Telegram-бот + веб-страница, которая внутри Telegram открывается как Mini App.
Ничего не надо устанавливать: в Telegram открывается Mini App, во всех остальных местах — та же ссылка в браузере.

## Как пользуются

1. Кто-то отправляет боту фото чека (или `/new Пятница`). Бот создаёт счёт с этим фото и присылает кнопку «Открыть счёт», её пересылают в общий чат.
2. Позиции вносятся вручную. Если админ включил OCR, под фото есть кнопка «🔍 Распознать», которая заполняет позиции сама. Длинный чек снимают по частям: в счёте кнопка «📎 Фото» позволяет выбрать сразу несколько фото, а в бот можно прислать их одним альбомом, и получится один счёт. Всего до 10 фото на счёт. «Распознать» читает все новые фото как один чек.
3. Каждый открывает счёт и тапает то, что ел. Повторный тап снимает отметку, `+`/`−` задают количество (например, 2 пива из 3), «всем» делит позицию на всех.
4. Внизу видно, кто сколько должен. Суммы округляются до тенге так, что сходятся с итогом в точности (метод наибольшего остатка).
5. «Кому переводить»: по умолчанию админу, на его номер и банки (например, `8 705 … · Freedom → Kaspi`). Если получатель другой, он вводит свой номер и отмечает банки в порядке приоритета, есть поле «Другой банк». Номер Telegram-участника может поменять только он сам: сервер проверяет подпись Telegram.
6. «📋 Итоги» копирует текст для чата вместе с реквизитами, а галочка «перевёл» показывает, кто уже рассчитался.

### Где найти свои счета

- **Кнопка «Счёт»** рядом с полем ввода в боте открывает главную Mini App со списком «Мои счета»: дата и время создания, 📍 заведение, 👥 число людей. Тап по строке открывает счёт, нативная кнопка «Назад» Telegram возвращает к списку.
- **`/bills`** в личке с ботом присылает тот же список кнопками.
- В список попадают счета, которые вы создали или в которых участвуете. **Админ видит все счета** и открывает чужие в режиме просмотра, не становясь участником. Чтобы участвовать, есть кнопка «Участвовать».
- Заведение вводится под названием счёта (поле «📍 Заведение»). При распознавании чека оно подставляется само, если поле ещё пустое.

### Сколько хранятся счета

Счёт удаляется вместе с фото через **14 дней после последнего изменения** (`BILL_TTL_DAYS`). Пока в счёте что-то отмечают, срок продлевается. Проверка идёт при старте и каждые 6 часов.

Друзей без Telegram можно добавить кнопкой «+ без Telegram» и отмечать позиции за них через «Отмечаю за».

## Запуск бота в Telegram

1. **Бот.** В @BotFather выполнить `/newbot` и сохранить токен.
2. **Публичный https-адрес.** Mini App открывается на телефонах друзей, поэтому сервер должен быть доступен из интернета по https. Варианты:
   - **ноутбук без домена и VPS** — см. [Запуск на ноутбуке](#запуск-на-ноутбуке-без-домена-и-vps);
   - VPS и свой домен: в `Caddyfile` строка `bill.example.kz { reverse_proxy localhost:8080 }`, сертификат Caddy получит сам.
3. **Mini App.** В @BotFather выполнить `/newapp`, указать URL = `PUBLIC_URL` и придумать short name.
4. **Запуск:**
   ```bash
   uv venv && uv pip install -r requirements.txt
   cp .env.example .env   # заполнить; узнать свой ADMIN_ID можно у @userinfobot
   set -a && . ./.env && set +a && .venv/bin/python app.py
   ```
   При старте бот сам регистрирует команды `/new` и `/help` и кнопку «Счёт» рядом с полем ввода. Админу дополнительно видны `/admin` и `/requisites`.
5. **Автозапуск** — пользовательский systemd-сервис [`splitbill.service`](splitbill.service), root не нужен. Если папка проекта другая, поправьте пути в файле.
   ```bash
   mkdir -p ~/.config/systemd/user && cp splitbill.service ~/.config/systemd/user/
   systemctl --user daemon-reload && systemctl --user enable --now splitbill
   loginctl enable-linger $USER    # запуск при включении ноутбука, ещё до входа в систему
   ```
   Управление:
   ```bash
   systemctl --user status splitbill        # состояние
   journalctl --user -u splitbill -f        # логи
   systemctl --user restart splitbill       # после изменения кода или .env
   systemctl --user stop splitbill          # перед ручным запуском (два бота с одним токеном = ошибка 409)
   ```
   Если процесс падает или при загрузке ещё нет сети, systemd перезапускает его через 10 секунд. Токены хранятся в `.env`, не в git.

Без `BOT_TOKEN` запускается только веб-интерфейс на `http://localhost:8080`.

### Запуск на ноутбуке без домена и VPS

Покупать домен не нужно. Бот получает сообщения сам (long polling), входящий доступ ему не требуется. Публичный https-адрес нужен только странице счёта, и его бесплатно даёт туннель.

**Tailscale Funnel (рекомендуется): постоянный адрес `https://<ноутбук>.<tailnet>.ts.net`.**

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up                    # вход через браузер, бесплатный тариф Personal
sudo tailscale funnel --bg 8080      # при первом запуске попросит включить HTTPS и Funnel в админке
tailscale funnel status              # здесь будет https-адрес — это PUBLIC_URL
```

- Адрес не меняется между перезапусками, поэтому ссылки на старые счета и Mini App в @BotFather продолжают работать.
- Роутер настраивать не нужно. Работает и за NAT провайдера, и без белого IP.
- После первого включения адрес может стать доступен в течение ~10 минут.
- Funnel открывает сервис всему интернету. Это нормально: доступ к счёту даёт только случайная ссылка, а админка работает лишь в боте.

**Cloudflare Quick Tunnel: только для быстрой проверки.** `cloudflared tunnel --url http://localhost:8080` выдаёт случайный адрес `*.trycloudflare.com`, и он **меняется при каждом перезапуске**. Тогда придётся обновлять `PUBLIC_URL` и URL Mini App в @BotFather (`/myapps`), а ссылки на старые счета перестанут открываться.

**Что учесть с ноутбуком:**
- Бот работает, только пока ноутбук включён, не спит и подключён к интернету. Чтобы закрытая крышка не усыпляла ноутбук: `HandleLidSwitch=ignore` в `/etc/systemd/logind.conf`, затем `sudo systemctl restart systemd-logind`.
- Автозапуск — шаг 5 выше. Tailscale сам поднимается после перезагрузки (`tailscaled` — системный сервис), `funnel --bg` настройку сохраняет.
- Все счета и фото лежат в `bills.db`. Стоит иногда копировать его в другое место.

### Группы

Бота добавляют в группу, `/new Пятница` создаёт счёт с кнопкой. Фото в группе бот увидит только при выключенном privacy mode (`/setprivacy` → Disable). Можно и проще: присылать фото боту в личку.

## Админка

Работает только в личке с ботом и только для `ADMIN_ID`:
- `/admin` — статус, кнопка «Включить/Выключить OCR», счётчик распознаваний за день;
- `/bills` — все счета за последние 14 дней;
- `/requisites 8 700 123 45 67 Freedom Kaspi` — реквизиты по умолчанию, банки перечисляются по приоритету. Если в названии банка есть пробел, банки разделяются запятыми.

Начальные значения берутся из `.env` (`ADMIN_PHONE`, `ADMIN_BANKS`), всё изменённое через бота хранится в БД.

## Распознавание чеков (OCR)

По умолчанию выключено, включается только админом через `/admin`. Работает через API-ключ или через Claude Code на этом же компьютере (см. ниже). Пока OCR выключен, фото просто прикрепляются к счёту, а кнопки «Распознать» нет. Каждое фото распознаётся один раз. Общий лимит на день задаётся в `OCR_DAILY_LIMIT` (по умолчанию 100) и защищает от неожиданного счёта за API.

Кнопка «🔍 Распознать» отправляет **все ещё не распознанные фото счёта одним запросом**: длинный чек, снятый в 2–3 кадра, читается как один, и строки на стыке кадров не дублируются.

Модель — `claude-haiku-5-5`, другую задаёт `OCR_MODEL`. Ответ приходит не свободным текстом, а JSON по единой схеме (`ocr.py`, `SCHEMA`):

```json
{
  "items": [
    {"name": "Комбо 1", "note": "не острое", "qty": 1, "price": 2690},
    {"name": "Сытное комбо", "note": "", "qty": 2, "price": 5980}
  ],
  "service_pct": 10, "service_amount": 2865, "total": 31515
}
```

- `price` — сумма строки (кол-во × цена), из неё считаются доли.
- `note` — короткий модификатор («острое»). Одно блюдо с разными модификаторами идёт отдельными позициями, чтобы каждый отметил своё.
- Содержимое комбо не становится отдельной позицией. Упаковка с ценой (супница, контейнер) — становится.
- Если итог в чеке не сходится с суммой позиций и обслуживанием, страница показывает предупреждение. Любую позицию можно поправить вручную.

Стоимость на Haiku 5.5 — доли цента за чек. Для мятых или блёклых чеков можно поставить `OCR_MODEL=claude-opus-5-5`: точнее, но примерно в 40 раз дороже.

### Почему JSON-схема, а не свободный текст

Если спросить модель «какие товары в чеке», ответ будет читаемым, но каждый раз в новом формате: «2 690,00 каждое (×3)», «4 шт., 760,00», «по 2 990». Программа не может надёжно вытащить из этого цифры. Структурированный вывод (`output_config.format`) заставляет модель ответить строго по схеме, и API гарантирует валидный JSON. Правила для спорных случаев (модификаторы, комбо, упаковка, перекрывающиеся фото) записаны в промпте `PROMPT` в `ocr.py`.

### Через API или через Claude Code

Промпт, схема ответа и модель одинаковые, отличается только способ вызова:

| | API (`OCR_BACKEND=api`) | Claude Code (`OCR_BACKEND=claude-code`) |
|---|---|---|
| Что нужно | `ANTHROPIC_API_KEY` | Claude Code установлен и залогинен на этом компьютере (`claude` → `/login`) |
| Оплата | по токенам с API-аккаунта, доли цента за чек | из лимитов вашей подписки Claude, общих с вашей обычной работой в Claude |
| Скорость | ~2–4 с | ~5–7 с (запуск процесса `claude`) |
| Подходит | публичному боту, любому серверу | своему боту на своём ноутбуке |

Если `OCR_BACKEND` не задан, используется API, когда `ANTHROPIC_API_KEY` заполнен, иначе Claude Code. В `/admin` видно, какой способ активен. Кнопка «Включить OCR» не сработает, если выбранный способ недоступен.

Как вызывается Claude Code: `claude -p` в режиме потокового ввода. Фото передаются прямо в сообщении, ответ проверяется по той же JSON-схеме (`--json-schema`). При этом:
- никакие инструменты не включены (`--tools ""`): Claude Code не может ни читать файлы, ни запускать команды;
- ваши хуки, плагины и MCP-серверы не загружаются (`--setting-sources ""`, `--strict-mcp-config`);
- запуск идёт из пустой временной папки, сессии не сохраняются.

Systemd-сервис запускается без `~/.local/bin` в `PATH`, поэтому `claude` ищется и там. Другой путь задаётся в `CLAUDE_BIN`.

Подписка Claude рассчитана на личное использование. Для своего бота на своём ноутбуке, которым пользуются друзья, этого обычно достаточно. Если бот станет публичным или нагрузка вырастет, переключитесь на API-ключ.

### Проверить на своих чеках

```bash
ANTHROPIC_API_KEY=... .venv/bin/python -c "
import ocr
photos = [(open(f, 'rb').read(), 'image/jpeg') for f in ['1.jpg', '2.jpg']]
print(ocr.recognize(photos))"
```

Все фото одного чека передаются вместе, как это делает кнопка «Распознать». Если модель ошибается на каком-то типе строк, поправить нужно правила в `PROMPT`.

## Файлы

- `app.py` — HTTP API, SQLite, Telegram-бот (long polling)
- `split.py` — расчёт долей и округление; `python split.py` запускает самопроверку
- `test_app.py` — сквозная проверка API без сети: подпись Telegram, реквизиты, фото, OCR через заглушку
- `ocr.py` — фото → позиции
- `index.html` — весь интерфейс
- `splitbill.service` — systemd-сервис для автозапуска
- `logo.svg` — логотип (исходник); `logo-512.png` — аватар бота: @BotFather → `/setuserpic`. Иконка вкладки встроена в `index.html`
- `miniapp-640x360.svg` / `.png` — превью Mini App, которое показывается при пересылке ссылки на приложение: @BotFather → `/myapps` → бот → «Edit Photo»

## Ограничения

- Доступ к счёту даёт ссылка (случайный id длиной 16 символов), как в Google Docs «по ссылке»: позиции и отметки может менять любой, у кого есть ссылка. Имя и реквизиты Telegram-участника меняет только он сам (подпись `initData` проверяется), гостей без Telegram — любой.
- Счётчик OCR за день хранится в памяти и обнуляется при перезапуске.
- Список счетов есть только в Telegram: сервер узнаёт человека по подписи Telegram. В обычном браузере доступна только ссылка на конкретный счёт.
- Синхронизация — опрос раз в 3 секунды, без websockets.
- Один процесс, одна глобальная блокировка на запись.
